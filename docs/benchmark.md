# Inbox query index benchmark

Generated by `npm run benchmark` (server/scripts/benchmark-index.js) on 2026-10-16.

**Data:** 100,000 emails in total; the demo user (id 1) has 2,075 in their inbox. PostgreSQL 18.6 (653b019) on Neon.

**Query** (the exact SQL `GET /api/emails` runs for page 1 of the inbox, built by `buildListQuery`):

```sql
SELECT id, sender_name, sender_email, recipient_email, subject,
left(body, 120) AS snippet, folder, is_read, is_starred, created_at
FROM emails
WHERE user_id = $1 AND folder = $2
ORDER BY created_at DESC
LIMIT $3 OFFSET $4
-- params: [1,"inbox",20,0]
```

**Index:**

```sql
CREATE INDEX idx_emails_user_folder_created ON emails (user_id, folder, created_at DESC);
```

| | Without index | With index |

| All runs (ms) | 12.913, 13.828, 13.856, 14.215, 13.193 | 0.126, 0.105, 0.114, 0.161, 0.124 |
| Seq Scan on emails | yes | no |

| Separate Sort step | yes | no |

Median went from 13.828 ms to 0.124 ms (112x faster). Plan changed from Seq Scan to Index Scan: yes.

Times are Postgres's own `Execution Time` from `EXPLAIN (ANALYZE, BUFFERS)`, so they don't include network latency. The median of 5 runs is used so a single slow (cold-cache) run doesn't skew the result.

## Why the column order is (user_id, folder, created_at)

An index is like a phone book: sorted by the first column, then the second, then the third.

- **user_id and folder come first because the query tests them with `=`.** All of one user's inbox emails sit next to each other in the index, so Postgres jumps straight to that block instead of reading the whole table.
- **created_at DESC comes last because it's the sort column.** Inside that block the entries are already in newest-first order, so Postgres reads the first 20 and stops. There's no Sort step and no need to look at the user's other emails.
- **The wrong order would not work as well.** With `(created_at, user_id, folder)`, one user's inbox would be scattered across the whole index. Postgres would have to walk through everyone's emails by date and throw away the ones that aren't this user's.
